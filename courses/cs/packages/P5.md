## cs.processor · Processor fundamentals and the fetch-execute cycle (`@time 5–7 hours`)
Outcomes (FACTS.md 4.1): Von Neumann model and the stored program concept; registers, general purpose vs special
purpose: PC, MDR, MAR, ACC, IX, CIR, Status Register; ALU, CU, system clock, Immediate Access Store (IAS); address,
data and control buses; performance factors: processor type and number of cores, bus width, clock speed, cache;
ports USB, HDMI, VGA; fetch-execute cycle stages in register transfer notation; interrupts: causes, applications,
the Interrupt Service handling Routine (ISR), when they are detected in the F-E cycle, how they are handled.
Cover: stored program concept (instructions and data in the same memory, fetched and executed in sequence);
each register's purpose in one exam sentence; ALU, CU (decodes, sends control signals), clock (synchronises), IAS
(main memory the CPU addresses directly); buses: address bus one-way CPU → memory (width sets addressable memory:
2ⁿ locations), data bus two-way (width sets bits per transfer), control bus (read/write, clock, interrupt signals);
performance factors with reasons (more cores: tasks in parallel, but not all programs can use them; wider data bus
moves more bits per cycle; faster clock: more cycles per second, heat; larger cache: fewer slow main-memory reads);
ports (USB: serial, many devices, power; HDMI: digital video and audio; VGA: analogue video); the F-E cycle in
register transfer notation:
`MAR ← [PC]`, `PC ← [PC] + 1`, `MDR ← [[MAR]]`, `CIR ← [MDR]`, then decode and execute (state that `[ ]` means
"contents of" and `[[MAR]]` is "the contents of the location whose address is in MAR"); interrupts: causes
(hardware: key press, printer out of paper; software: division by zero, request for I/O; timer), detected at the
end of each cycle, priority check, current register contents saved (on a stack), ISR address loaded into PC, ISR
runs, registers restored, cycle resumes.
- `:::def`: stored program concept, register, PC, MAR, MDR, CIR, ACC, IX, status register, ALU, CU, system clock,
  IAS, address bus, data bus, control bus, cache, interrupt, ISR.
- Pitfalls: MAR holds an address, MDR holds data or an instruction; the PC is incremented during fetch, not after
  execute; the address bus is one-way; "more cores always doubles speed" is wrong.
- Exam-style: complete the register transfer description; explain how bus width affects performance (2);
  describe how an interrupt is handled (5); identify the register for a description.
- Figures: hand SVG of the Von Neumann CPU (CU, ALU, registers, buses to memory and I/O), fig.
- Widget **cs-asm** in the F-E section (step mode).
- Links: SME `4-processor-fundamentals-/central-processing-unit-cpu-architecture/exam-questions/`, 101 Computing
  LMC simulator, Computerphile.
- `Next: [Assembly language and bit manipulation](#cs.assembly)`.

## cs.assembly · Assembly language and bit manipulation (`@time 6–8 hours`)
Outcomes (FACTS.md 4.2, 4.3): relationship between assembly language and machine code; stages of a two-pass
assembler and applying them to a simple program; tracing a simple program; instruction groups (data movement,
input and output, arithmetic, unconditional and conditional instructions, compare); addressing modes immediate,
direct, indirect, indexed, relative; binary shifts: logical, arithmetic and cyclic, left and right; bit manipulation
to monitor/control a device; test and set a bit with masks.
Cover: machine code (binary opcode + operand) and mnemonics, one-to-one translation; two-pass assembler (pass 1:
read each line, build the symbol table of labels and their addresses, handle directives, remove comments; pass 2:
generate machine code using the symbol table, opcode lookup); each instruction from FACTS.md with an example and its
group; addressing modes with a memory table (immediate #n is the value; direct is the address of the value; indirect
is the address of the address; indexed is address + IX; relative is an offset from the current instruction's
address: say that Cambridge's example table has no relative instruction, so questions that use it will define it);
tracing a program in a trace table with columns for ACC, IX, memory locations and OUTPUT (the style Paper 1
prints); loops with CMP/JPE/JPN; IN/OUT with ASCII values (give the codes in the question); shifts: LSL/LSR in
the instruction set, multiplication/division by powers of 2 (unsigned), arithmetic shift keeps the sign bit, cyclic
shift moves the bit out into the other end; masks: AND to test/clear a bit, OR to set a bit, XOR to toggle; a device
register example (8 sensors as 8 bits; test bit 3; switch on a light).
- `:::def`: machine code, assembly language, opcode, operand, mnemonic, assembler, symbol table, each addressing
  mode, logical shift, arithmetic shift, cyclic shift, mask.
- Pitfalls: LDD 50 loads the contents of 50, LDM #50 loads the number 50; INC/DEC change a register, not memory;
  JPE/JPN act on the last CMP; logical right shift of a negative two's complement number does not halve it.
- Exam-style: trace a 10–14 line program with a given memory table and instruction-set table (print the table in the
  question); write a short program (add two numbers, count to 5, loop with IX); complete the symbol table for pass
  1; write the instruction to set/clear/test a bit.
- Figures: memory tables as Markdown tables (addresses and contents).
- Widget **cs-asm** (program mode).
- Links: SME `4-processor-fundamentals-/assembly-language-/exam-questions/` and `…/bit-manipulation/exam-questions/`,
  101 Computing LMC simulator.

## Widget spec: cs-asm
`<div class="widget" data-w="cs-asm" data-program="sum" data-mode="fe"></div>`
- A simulator of exactly the FACTS.md instruction set (LDM LDD LDI LDX LDR MOV STO ADD SUB INC DEC JMP CMP CMI JPE
  JPN IN OUT END AND OR XOR LSL LSR; operands #n, Bn, &n, addresses and labels). Built-in programs by name
  (`sum`, `countdown`, `indexed` (adds an array with IX), `mask`) plus an editable text area for the reader's own
  program. Memory shown as a table (address, label, contents); registers PC, CIR, MAR, MDR, ACC, IX and the compare
  result; an OUTPUT line (characters from OUT). IN reads from a small "keyboard buffer" field.
- Mode `fe`: Step shows each fetch micro-step in register transfer notation (`MAR ← [PC]` …) before executing.
  Mode `run`: Step executes one instruction; Run (with Pause) runs to END with a step limit of 1000 (infinite loop →
  message).
- Parse errors name the line. Test with a Node script running each built-in program against the Python simulator in
  checks/cs.assembly.py.
