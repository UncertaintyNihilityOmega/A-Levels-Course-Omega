## cs.paradigms · Programming paradigms: low-level, imperative and declarative (`@time 5–7 hours`)
Outcomes (FACTS.md 20.1, except OOP which is cs.oop): what a programming paradigm is; characteristics of low-level,
imperative (procedural), object-oriented and declarative paradigms; low-level: understand and write low-level code
using immediate, direct, indirect, indexed and relative addressing; imperative: write code with variables,
constructs, procedures and functions (assumed from AS); declarative: solve a problem by writing facts and rules from
supplied information, and write code that satisfies a goal using facts and rules.
Cover: paradigm definition and a comparison table (how a program is expressed; what the programmer controls; typical
uses); low-level programming using the FACTS.md instruction set: programs with loops and IX (indexed) to total an
array, indirect addressing to follow a pointer, relative addressing described (an address given as an offset from the
current instruction; questions define the instruction they use); imperative: a short summary of AS structured
programming with one example (link to cs.procedures), state changed by assignments step by step; OOP: one paragraph
and a link to [Object-oriented programming](#cs.oop); declarative: Prolog-style syntax as Cambridge papers use it
(facts `capital(france, paris).`, rules `fly_to(X, Y) :- …`, variables start with a capital letter, constants lower
case, goals/queries and their results, `NOT`/`\+` only if you are sure of the form used: prefer writing negation in
words in the clause and avoid it), writing facts and rules from a description (a family tree, a course-prerequisite
database, a holiday booking), stating the results of a goal, backtracking described in words.
- `:::def`: programming paradigm, low-level programming, imperative programming, procedural programming,
  object-oriented programming, declarative programming, fact, rule, goal, clause, backtracking, each addressing mode.
- Pitfalls: in Prolog-style code variables are capitalised, facts end with a full stop; declarative says *what*, not
  *how*; indirect vs indexed addressing.
- Exam-style (P3): write facts and rules from a scenario (4); state the result of a goal (2); write a low-level loop
  using indexed addressing to add six numbers (6); compare imperative and declarative (3).
- Checks: a Python model of the facts and rules (sets and comprehensions) recomputes every goal result in the chapter;
  the assembly programs run in a small Python simulator of the instruction set (as P5's checks do).
- Links: SME `20-further-programming-/programming-paradigms/exam-questions/`, SWISH, Computerphile.

## cs.fileproc · File processing and exception handling (`@time 5–7 hours`)
Outcomes (FACTS.md 20.2): write code to open (read, write, append) and close a file; read a record from a file and
write a record to a file; perform file-processing operations on serial, sequential and random files; understand
exceptions and the importance of exception handling; know when it is appropriate; write code that uses exception
handling.
Cover: pseudocode for text files (recap, FACTS.md) and random files (OPENFILE … FOR RANDOM, SEEK, GETRECORD, PUTRECORD);
Python: `open` modes `"r"`, `"w"`, `"a"`, `with` blocks, reading lines, `strip()`, `split(",")`, writing records as
comma-separated lines, converting types; serial file (append records in arrival order), sequential file (kept in key
order: insert a record by copying to a new file; search can stop early when the key is passed; merge two sorted
files), random-access file in Python with fixed-length records (pad fields to fixed width, record number × record
length with `seek`, read/write in place; or `pickle` one record at a time only if you explain it simply: prefer
fixed-width text records, which Paper 4's "source files will not contain binary files" suits); updating a record;
exceptions (an unexpected event at run time that disrupts the normal flow: file not found, division by zero, invalid
conversion, index out of range); `try`/`except` with specific exception types (`FileNotFoundError`, `ValueError`,
`ZeroDivisionError`, `IndexError`), `else`, `finally`, raising an exception; pseudocode has no exception keyword in the
guide: questions describe it in words, so answers in pseudocode describe the handling (say so); when handling is
appropriate (input from users, files, network; not to hide logic errors).
- `:::def`: serial file, sequential file, random file, record, field, file mode, exception, exception handling, try
  block, except block.
- Pitfalls: opening in `"w"` deletes the contents; forgetting `strip()` leaves `"\n"` on the last field; catching every
  exception with a bare `except` hides bugs; closing a file that failed to open.
- Exam-style (P4): read a given file of records into an array of objects, handle a missing file with an exception, and
  output a summary (10–12); write records back sorted (6); (P3) explain why exception handling is important (2).
- Links: SME `20-further-programming-/file-processing-and-exception-handling/exam-questions/`, Python tutorial
  input/output and errors, W3Schools file handling and try/except.
- `Next: [Python for Paper 4: the practical toolkit](#cs.python)`.

## cs.python · Python for Paper 4: the practical toolkit (`@time 5–7 hours`)
A skills chapter (not a new syllabus section): everything a Python candidate needs to turn Paper 4 tasks into
working, evidenced code. Outcomes: FACTS.md 19.1, 19.2, 20.1 (OOP), 20.2 as they appear in Paper 4; plus the Paper 4
procedure (FACTS.md "Paper 4": evidence document, saving files with the given names, screenshots of output, no
internet).
Cover: reading a Paper 4 task (identifier names and array sizes are given: use them exactly; "global" arrays;
indexes from 0 when the task says 0–19); declaring and initialising global 1D and 2D lists (`[-1] * 20`,
`[[0] * 5 for _ in range(4)]`, never `[[0] * 5] * 4`: link to the gold chapter's warning); records as classes with
`__init__` (FACTS.md: "A class declaration can be used to declare a record"); `global` inside functions; string
handling (slicing, `split`, `strip`, `upper`, `isdigit`, `str()`/`int()`/`float()`, `ord`/`chr`, formatting with
f-strings and `round`); reading the given text files (`with open(...)`, loops, `strip`, `split`), writing files;
exceptions around file opening; input validation loops; testing: running the given test data, producing the exact
output requested, screenshots of the console in the evidence document; common errors under time pressure and how to
read a traceback quickly; a pseudocode → Python translation table for every pseudocode construct (FACTS.md) including
`DIV` → `//`, `MOD` → `%`, `MID(S, X, Y)` → `S[X - 1:X - 1 + Y]`, `INT` → `int`, `RAND(X)` → `random.random() * X`,
`REPEAT … UNTIL` → `while True … break`, `BYREF` → return the value or use a list/global, `CLASS … INHERITS` → `class
B(A):`; time management for 2 h 30 min and 75 marks (about two minutes per mark as an arithmetic fact, stated as such);
a complete mini task (circular queue or file-splitting style, original) solved with evidence-style output.
- `:::def`: evidence document, global variable, list, list comprehension (only the simple form), f-string, traceback.
- Pitfalls: wrong file names/paths (keep the text files in the same folder as the program); off-by-one with
  0-based lists; shadowing built-ins (`list`, `max`, `input`) with variable names; integer division `//` vs `/`.
- Exam-style: three P4-style tasks of 8–12 marks each with expected outputs and mark points (one per mark).
- Links: Python tutorial, W3Schools Python, Exercism Python, PMT Paper 4 past papers, Python Tutor.
