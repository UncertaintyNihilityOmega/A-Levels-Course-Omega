## cs.recursion · Recursion (`@time 5–7 hours`)
Outcomes (FACTS.md 19.2): essential features of recursion; how recursion is expressed in a programming language;
write and trace recursive algorithms; when recursion is beneficial; what a compiler has to do to translate recursive
code (use of stacks and unwinding).
Cover: definition (a subroutine that calls itself); essential features: a base case that stops it, a general
(recursive) case that moves towards the base case; factorial, sum of a list, power, string reversal, counting digits,
Fibonacci (and why naive Fibonacci is slow: count calls in the checks), recursive binary search and in-order tree
traversal (link to cs.adts); tracing with a call tree and with a table of calls and return values (Cambridge asks for
"the output" or "the value returned" of given recursive pseudocode); the call stack: each call pushes a stack frame
(return address, parameters, local variables), the base case returns, frames are popped as the calls unwind; stack
overflow when there is no base case or the depth is too large (Python's recursion limit: show `RecursionError` caught
in the checks); recursion vs iteration (benefits: shorter, natural for trees and divide-and-conquer; drawbacks: memory
for frames, slower, risk of overflow); converting a simple recursive function to iteration and back.
- `:::def`: recursion, base case, general case, call stack, stack frame, unwinding, stack overflow.
- Pitfalls: base case missing or never reached; returning the recursive call's result vs ignoring it; output before or
  after the recursive call changes the order (trace both).
- Exam-style (P3): trace given recursive pseudocode and state the output (4); explain how the stack is used when the
  call is made with a given value (4). (P4): write a recursive function and test it (5–7).
- Widget **cs-calls** in the call-stack section.
- Links: SME `19-computational-thinking-and-problem-solving-/recursion/exam-questions/`, VisuAlgo recursion, Python
  Tutor, Khan algorithms (recursion).

## cs.oop · Object-oriented programming (`@time 7–9 hours`)
Outcomes (FACTS.md 20.1, OOP part): terminology: objects, properties/attributes, methods, classes, inheritance,
polymorphism, containment (aggregation), encapsulation, getters, setters, instances; solve a problem by designing
appropriate classes; write code that uses OOP.
Cover: class as blueprint, object as instance; attributes and methods; constructor (pseudocode `NEW`, Python
`__init__`); encapsulation with PRIVATE attributes and PUBLIC getters/setters (pseudocode syntax from FACTS.md;
Python convention: `self.__name` name-mangled private attributes, as Cambridge Paper 4 Python mark schemes commonly
use double underscores: present it as "the convention used in this course" without claiming what mark schemes
require); getters and setters with validation in the setter; inheritance (`CLASS Cat INHERITS Pet`, `SUPER.NEW`;
Python `class Cat(Pet):`, `super().__init__`); polymorphism (method overriding: a subclass's own version of a method;
calling the same method on a list of mixed objects); containment/aggregation (a class has attributes that are objects
of another class: a Library containing Books; difference from inheritance: "has a" vs "is a"); class diagrams (three
compartments: name, attributes with types, methods; inheritance arrow; draw as hand SVG); designing classes from a
scenario (identify nouns → classes/attributes, verbs → methods); a Paper 4 style task built step by step: declare the
class, constructor, getters, a method, create instances from a file or a list, output results (with the output
checked).
- `:::def`: class, object, instance, attribute (property), method, constructor, encapsulation, getter, setter,
  inheritance, superclass, subclass, polymorphism, overriding, containment (aggregation).
- Pitfalls: forgetting `self`; calling a method without brackets; changing a private attribute directly from outside;
  inheritance used where containment fits; constructor named wrongly in pseudocode (it is `NEW`).
- Exam-style (P3): complete a class diagram from a description (4); write pseudocode for a class with a constructor and
  getters (6). (P4): a 15–20 mark task with a parent class and a subclass, overriding, a list of objects, and test
  output.
- Figures: hand SVG class diagrams (two), coordinates checked.
- Links: SME `20-further-programming-/object-oriented-programming/exam-questions/`, Python tutorial classes, W3Schools
  Python classes.
- `Next: [Programming paradigms: low-level, imperative and declarative](#cs.paradigms)`.
