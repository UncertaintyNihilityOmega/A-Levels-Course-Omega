## cs.procedures · Procedures, functions and parameters (`@time 6–8 hours`)
Outcomes (FACTS.md 11.3): define and use a procedure and explain where in an algorithm it is appropriate; use
parameters (none, one or more; passed by reference or by value); define and use a function and explain where it is
appropriate (used in an expression: the return value replaces the call); the terms procedure/function header,
interface, parameter, argument, return value; write efficient pseudocode.
Cover: why modules (decomposition from cs.algorithms, reuse, testing, teamwork, readability); PROCEDURE … ENDPROCEDURE
with CALL; parameters and arguments (the guide's wording: parameters in the header, arguments in the call; types and
order must match); BYVAL (a copy) and BYREF (the original variable changes) with a trace showing both, the guide's
SWAP example rewritten with your own data; FUNCTION … RETURNS … RETURN … ENDFUNCTION called inside an expression,
never with CALL, never BYREF; local vs global variables and scope (with the pitfalls of globals); header and interface
(the name, parameters with types, return type); returning early; modules that use arrays (pass an array, return a
count); Python: `def`, `return`, default by-object behaviour (immutable arguments behave like BYVAL; lists can be
changed inside a function so they behave like BYREF; to mimic BYREF for a number, return the new value), `global`;
Paper 2 style "write a function that …" questions built around a scenario (validate a password, convert a date
string, count matching records); efficient pseudocode (exit loops early, avoid repeated calls in a condition).
- `:::def`: procedure, function, parameter, argument, return value, header, interface, by value, by reference, local
  variable, global variable, scope, module.
- Pitfalls: using CALL with a function; a function that OUTPUTs instead of RETURNing; changing a BYVAL parameter and
  expecting the caller to see it; Python cannot pass an int by reference; forgetting the RETURNS type.
- Exam-style: write a function header from a description (2); write a whole function with a loop and string
  functions (6–8); state the output of a program that calls a BYREF procedure; explain why a function is more
  appropriate than a procedure here.
- Figure: hand SVG of a call and return (caller → procedure with arguments → back) or a small structure-chart preview
  (cs.development draws structure charts in full).
- Links: SME `11-programming-/structured-programming/exam-questions/`, W3Schools Python functions, Python Tutor.
- `Next: [Text files, stacks, queues and linked lists](#cs.structures)`.

## cs.structures · Text files, stacks, queues and linked lists (`@time 6–8 hours`)
Outcomes (FACTS.md 10.3, 10.4): why files are needed; pseudocode to handle text files of one or more lines; an ADT is
a collection of data and a set of operations on those data; stack, queue and linked list are ADTs; their key
features and justify their use; use them to store data (add, edit, delete; no pseudocode required at AS for these
structures, but show it so students understand); how a stack, queue and linked list can be implemented using arrays.
Cover: files (data persists after the program ends; share data between programs; large data); OPENFILE … FOR READ /
WRITE / APPEND, READFILE, WRITEFILE, EOF, CLOSEFILE (FACTS.md) with full examples (copy lines, count lines, search a
file, append a record as a comma-separated line and read it back by splitting with string functions); Python `open`
with `with`, `readline`/iteration, `strip()`, `write` with `"\n"`, modes `"r"`, `"w"`, `"a"` (all examples write
their own files so checks can run them in a temporary folder); ADT idea; stack (LIFO; push, pop, peek; top pointer;
stack overflow/underflow; uses: undo, back button, call stack, reversing); queue (FIFO; enqueue, dequeue; front and
rear pointers; linear queue problem and the circular queue with MOD; uses: print queue, buffers, scheduling);
linked list (nodes with data and a pointer; start pointer; null pointer −1 or 0 as the question says; free list;
insert in order and delete by pointer changes, shown as before/after tables); array implementations as tables with
indexes; "justify" answers (why a queue for a printer, why a linked list when inserting in order often).
- `:::def`: text file, file mode, EOF, abstract data type, stack, queue, circular queue, linked list, node, pointer,
  null pointer, free list, LIFO, FIFO, stack overflow, stack underflow.
- Pitfalls: WRITE erases the file (APPEND adds); reading past EOF; forgetting CLOSEFILE; pop from an empty stack;
  a linear queue "full" with empty space at the front; losing the rest of a linked list by changing pointers in the
  wrong order.
- Exam-style: Paper 2 style: complete a stack/queue diagram after a sequence of operations with pointers (as in the
  May/June 2025 paper's style, original data); write pseudocode that reads a file and counts lines matching a
  condition (6); describe how to add a node to a linked list stored in arrays (4).
- Widget **cs-stack** in the ADT sections.
- Links: SME `10-data-types-and-structures-/files/exam-questions/` and
  `…/introduction-to-abstract-data-types-adt/exam-questions/`, VisuAlgo list, USF visualisations, W3Schools file
  handling.

## Widget spec: cs-stack
`<div class="widget" data-w="cs-stack" data-type="stack" data-size="8"></div>`
- Types (`.w-tabs`, start from `data-type`): **stack** (array with TopPointer; Push value / Pop), **queue** (linear
  queue with FrontPointer, RearPointer), **circular** (circular queue with front, rear and a count, MOD arithmetic),
  **list** (linked list in two arrays Data[] and Pointer[] with StartPointer and FreePointer; Insert in order, Delete
  a value, Find). The arrays are drawn as tables with indexes 0 or 1 (`data-base="1"` default 1), pointer values shown
  as numbers and as "← Top"/"← Front" text markers. Every operation writes a one-line explanation ("Pushed 7 at
  index 3; TopPointer = 3") into a live region; errors (overflow, underflow, empty, not found) are messages, never
  exceptions.
- Values typed in a field (integers or short strings). Test every operation sequence in Node against a Python model
  in data/.

## Writer's notes
Written by the P9 Writer (14 November 2026). cs.datatypes untouched; no mistakes found in it.
- cs.procedures (about 8.9k words by the kit's count) and cs.structures (about 9.4k): every Python block runs and
  matches its output block; every pseudocode algorithm, trace table, before/after pointer table and stated value is
  recomputed in checks/<id>.py. Figures checked with data/p9_figcheck.py (label boxes against lines and edges).
- Pseudocode facts taken from the Pseudocode Guide itself (section 8, 9, downloaded and read): empty brackets
  `PROCEDURE Name()` and `CALL Name()`; BYVAL is the default; "the BYVAL or BYREF keyword need not be repeated"
  (the chapter repeats it every time); READ/WRITE/APPEND, WRITE loses existing data. The guide has NO syntax for an
  array parameter, so modules use a global array, as Paper 2 does, and the chapter says so.
- Identifiers avoid the insert's function names (DAY, MONTH, YEAR, LENGTH ...), because identifiers are case
  insensitive: TheYear, DayNumber, MonthNumber, Increase (STEP is a keyword).
- Conventions used for ADTs (stated in the chapter, "a question tells you its own"): arrays from 1; stack empty when
  TopPointer = 0; linear queue FrontPointer 1 and RearPointer 0 at the start, empty when Front > Rear; circular queue
  uses a Count and `Rear MOD size + 1`; linked list null pointer 0, free list through the Pointer array, insert
  before the first node that is not smaller. cs-stack follows exactly these (base 0 variant uses base - 1 as null).
- Reviewer: cs.structures uses `cs.algorithms`/`cs.programming` only as links; the circular-queue and linked-list
  trace tables use blank cells for "unchanged" as COURSE.md says.
- Widget cs-stack: tabs Stack, Queue, Circular queue, Linked list; extras beyond the spec are `data-items`,
  an Empty button and a Peek button; stale array values show in brackets and italic. Tests: data/cs-stack.test.js
  (600 random sequences against a Python model, 153,894 comparisons, sizes 3 to 12, base 0 and 1) and
  data/cs-stack.ui.test.js (buttons, tabs, Enter key, messages through a fake DOM).
