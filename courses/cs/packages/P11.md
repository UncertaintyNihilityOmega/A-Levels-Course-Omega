## cs.usertypes · User-defined types, file organisation and hashing (`@time 5–7 hours`)
Outcomes (FACTS.md 13.1, 13.2): why user-defined types are necessary; non-composite types: enumerated and pointer;
composite types: set, record, class/object; choose and design a type for a problem; methods of file organisation
(serial, sequential using a key field, random using a record key) and choosing one with an access method for a
problem; sequential access for serial and sequential files; direct access for sequential and random files; hashing
algorithms to read from and write to a random/sequential file.
Cover: the guide's syntax exactly (FACTS.md): `TYPE Season = (…)`, `TYPE TIntPointer = ^INTEGER`, `MyPointer ←
^Var`, `MyPointer^`, records, `TYPE LetterSet = SET OF CHAR` with `DEFINE`, class mention (full OOP in cs.oop);
what each is for, with a design question (a type for a booking system); Python equivalents (`enum.Enum`, a class,
`set`; Python has no pointer type: explain references instead); serial (in order of arrival: log files,
transactions), sequential (sorted by key: master files, batch updates, merging), random (records placed by hashing the
key: fast direct access); sequential access (read from the start) vs direct access (go straight to a record, via an
index for sequential files or a hash for random files); hashing: key MOD number of slots (+1 if addresses start at 1),
folding, collisions and handling them (next free slot/open addressing, overflow area), searching after collisions,
deleting with a marker; pseudocode with SEEK/GETRECORD/PUTRECORD (FACTS.md random files); choosing organisation for
scenarios (payroll run vs airline seat lookup).
- `:::def`: user-defined data type, non-composite data type, composite data type, enumerated type, pointer, set,
  record, serial file, sequential file, random file, sequential access, direct access, hashing algorithm, collision.
- Pitfalls: an enumerated type's values are not strings; a set has no order and no duplicates; serial ≠ sequential
  (sequential is sorted by a key); a hash must give the same address every time; collisions are normal, not errors.
- Exam-style: declare an enumerated type and a record using it (3); write pseudocode to store a record in a random file
  using a given hash function with linear probing (6); justify sequential organisation for a monthly payroll.
- Python: an open-addressing hash table on a list of fixed size (runs and output checked); writing and reading fixed
  records (cs.fileproc does file-level random access in Python).
- Links: SME `13-data-representation-/user-defined-data-types/exam-questions/` and
  `…/file-organisation-and-access-/exam-questions/`, VisuAlgo hashtable.

## cs.float · Floating-point numbers (`@time 5–7 hours`)
Outcomes (FACTS.md 13.3): format of binary floating-point real numbers with two's complement mantissa and exponent;
effect of changing the allocation of bits between mantissa and exponent; convert floating point to denary and back;
normalise and the reasons for normalisation; consequences of a binary representation being only an approximation;
underflow and overflow; rounding errors.
Cover: fixed point first (binary point, place values ½, ¼ …); floating point as mantissa × 2^exponent, both two's
complement, mantissa with the binary point after the sign bit (0.1101… form, as Cambridge uses); converting to denary
(exponent first, move the point, read the value) with positive and negative mantissas; denary to floating point
(write in binary, normalise, find the exponent); normalisation rule (positive mantissa starts 0.1, negative starts
1.0; maximises precision for the bits, gives a unique representation); largest/smallest positive values and the
most negative value for a given format (e.g. 8-bit mantissa, 4-bit exponent); more mantissa bits = more precision,
more exponent bits = more range; values that cannot be represented exactly (0.1 in binary; show `0.1 + 0.2` in
Python and explain), rounding errors accumulating in loops (compare with an integer counter), overflow (exponent too
large) and underflow (too close to zero, becomes 0).
- `:::def`: fixed-point representation, floating-point representation, mantissa, exponent, normalisation, precision,
  range, overflow, underflow, rounding error.
- Pitfalls: forgetting that the exponent is two's complement; normalising a negative number to 0.1…; shifting the
  point the wrong way for a negative exponent; "more bits for the exponent improves accuracy" (it improves range).
- Exam-style: convert a 12-bit floating-point number (8 + 4) to denary (3); write the normalised form of a denary value
  (3); explain why normalisation is used (2); state the effect of moving one bit from mantissa to exponent (2).
- Python: a converter for a given bit allocation (runs; checks assert every number in the chapter, computed with
  `fractions.Fraction`).
- Widget **cs-float** after normalisation.
- Links: SME `13-data-representation-/floating-point-numbers-representation-and-manipulation/exam-questions/`,
  101 Computing floating point converter.

  encode (nearest representable value, with the rounding error shown). Shows the mantissa as a two's complement
  fraction, the exponent in denary, the value as a fraction and a decimal, "normalised" or "not normalised (why)",
  a Normalise button that shifts and adjusts the exponent step by step, and the format's largest, smallest positive
  normalised and most negative values. Overflow/underflow messages in words.
- Exact arithmetic with integers (no floating-point drift in the display). Test against Python `Fraction` values.
