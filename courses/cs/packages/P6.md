## cs.software · System software: operating systems and translators (`@time 4–6 hours`)
Outcomes (FACTS.md 5.1, 5.2): why a computer needs an OS; the OS management tasks: memory, file, security, hardware
(input/output/peripherals) and process management; utility software: disk formatter, virus checker,
defragmentation software, disk contents analysis/disk repair, file compression, back-up software; program
libraries, DLL files and their benefits to the developer; the need for an assembler, a compiler and an interpreter;
benefits and drawbacks of compiler vs interpreter, justify each; partial compilation and interpretation (Java);
IDE features for coding (context-sensitive prompts), initial error detection (dynamic syntax checks), presentation
(prettyprint, expand and collapse code blocks) and debugging (single stepping, breakpoints, report window of
variables/expressions).
Cover: OS as the interface between user/applications and hardware; each management task in two or three exam
sentences (memory: allocate and protect memory for processes; file: directories, naming, permissions; security:
user accounts, access rights; hardware: drivers, I/O, buffers, interrupts; process: scheduling, multitasking;
A Level detail comes in cs.os); each utility: what it does and why it is needed (defragmenter puts file fragments
in contiguous sectors on a magnetic disk, so fewer head movements; not needed for SSDs); libraries (pre-written,
tested routines; saves time; DLLs are linked at run time, shared by programs, smaller executables, one update fixes
all, but a missing or wrong-version DLL breaks programs); translators: assembler (assembly → machine code, one to
one), compiler (whole program → object code/executable, reports all errors after translating, fast to run, source
hidden), interpreter (translates and executes line by line, stops at the first error, easier debugging, needs the
interpreter to run); Java bytecode run by a virtual machine; IDE features with what each does for the programmer
(say what Python's IDLE has, in general terms).
- `:::def`: operating system, utility software, defragmentation, program library, DLL, assembler, compiler,
  interpreter, IDE, breakpoint, single stepping, prettyprint.
- Pitfalls: "a compiler runs the program" (it translates); an interpreter does not create an executable; disk
  formatter vs defragmenter; "DLLs make programs faster" (the benefit is sharing and size).
- Exam-style: justify a compiler for a commercial release and an interpreter during development; describe three IDE
  debugging features; state four OS tasks.
- Links: SME `5-system-software-/operating-systems/exam-questions/` and `…/language-translators/exam-questions/`.

## cs.security · Security, privacy and data integrity (`@time 4–6 hours`)
Outcomes (FACTS.md 6.1, 6.2): difference between security, privacy and integrity of data; need for security of
data and of the system; measures from a stand-alone PC to a network: user accounts, passwords, authentication (digital
signatures, biometrics), firewall, anti-virus, anti-spyware, encryption; threats: malware (virus, spyware), hackers,
phishing, pharming; methods to restrict the risks; security methods for data: encryption, access rights; how
validation and verification protect integrity; validation: range, format, length, presence, existence, limit
check, check digit; verification during entry (visual check, double entry) and transfer (parity check, byte and
block; checksum).
Cover: definitions with examples; each measure (what it is, how it protects); each threat (how it works, what it does,
how to defend); access rights (read, write, execute; per user or group); validation vs verification (validation:
is it reasonable? verification: was it copied/transferred correctly?); each validation check with a pseudocode or
Python test (range `Age >= 11 AND Age <= 19`; format with string functions; length; presence; existence (value is in
a list/file); limit (one boundary); check digit: modulo-11 weighting worked in full); parity (even/odd, the parity bit
as MSB or LSB as the question says), block parity grid locating a single flipped bit, why two errors can pass;
checksum (sum of the bytes, transmitted and recalculated; a simple modulo-256 example).
- `:::def`: data security, data privacy, data integrity, firewall, malware, virus, spyware, phishing, pharming,
  biometrics, validation, verification, check digit, parity bit, checksum.
- Pitfalls: validation does not prove data is correct; phishing (email/message) vs pharming (redirect to a fake site
  via DNS/malicious code); encryption does not stop interception, it makes data unreadable.
- Exam-style: choose and justify validation checks for fields on a form; complete a parity block and locate the error;
  calculate a modulo-11 check digit; describe how a firewall protects a network.
- Widget **cs-check** in the verification section.
- Links: SME `6-security-privacy-and-data-integrity-/data-security/exam-questions/` and `…/data-integrity/exam-questions/`,
  Khan cryptography.

## cs.ethics · Ethics, ownership and the impact of AI (`@time 3–4 hours`)
Outcomes (FACTS.md 7.1): need for and purpose of ethics as a computing professional; importance of joining a
professional ethical body including BCS and IEEE; acting ethically or unethically in a given situation and its
impact; need for copyright legislation; types of software licence (Free Software Foundation, Open Source Initiative,
shareware, commercial) and justifying one; AI: applications and impact (social, economic, environmental).
Cover: what professional ethics means (public interest, competence, honesty, confidentiality, duty to the profession);
what BCS and IEEE do (codes of conduct, professional standards, development, a voice for the profession; state only
what their own sites say, in general terms); scenario analysis (a developer asked to hide a known bug, collect data
without consent, copy code); copyright (protects the creator's work; software piracy; why legislation is needed);
licences: free software (FSF: freedom to run, study, modify, share; copyleft), open source (OSI: source available,
licence conditions vary), shareware (free trial, then pay), commercial (paid licence, no source, restrictions);
which to choose for a scenario; AI applications (medical diagnosis, autonomous vehicles, fraud detection, language
translation, recommendation) and impacts: social (bias, privacy, jobs), economic (productivity, job change, cost),
environmental (energy used for training and data centres; optimisation of energy use); keep claims general and
true, no statistics unless sourced.
- `:::def`: ethics, professional ethical body, copyright, software licence, free software, open source software,
  shareware, commercial software, artificial intelligence.
- Pitfalls: "free software" means freedom, not price; open source is not always free of conditions; ethics vs law.
- Exam-style: discuss the impact of a given AI system (6, structured: social, economic, environmental); justify a
  licence for a scenario; explain two actions in a scenario that are unethical and why.
- Links: BCS, Open Source Initiative licences, ICO for organisations, Computerphile.

## Widget spec: cs-check
`<div class="widget" data-w="cs-check" data-mode="parity" data-parity="even"></div>`
- **Parity** tab: a 7 × 8 grid of bit buttons (7 data bytes + parity byte) with even/odd toggle; parity bits computed
  per row and per column; "Corrupt a bit" (random, seeded) or click a bit to flip it; the widget reports which row and
  column fail and the bit at the intersection ("Error at byte 4, bit 3"). **Check digit** tab: enter digits, choose
  modulo-11 weights (descending from n+1, as the chapter uses), see each product, the sum, the remainder and the check
  digit (10 shown as X); "Verify" for a code with its check digit.
- Text, not colour, marks failing rows (✗). Test against the chapter's checks file values.
