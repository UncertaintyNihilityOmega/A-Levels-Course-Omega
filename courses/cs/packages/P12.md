## cs.networks2 · Protocols, TCP/IP and packet switching (`@time 4–6 hours`)
Outcomes (FACTS.md 14.1, 14.2): why a protocol is essential; protocol implementation viewed as a stack with each
layer having its own function; the TCP/IP suite's four layers (Application, Transport, Internet, Link), purpose and
function of each, applied when a message is sent from one host to another on the internet; HTTP, FTP, POP3, IMAP,
SMTP, BitTorrent and their purposes (BitTorrent: peer-to-peer file sharing); circuit switching and packet switching
(benefits, drawbacks, where applicable); the function of a router in packet switching; how packet switching passes
messages across a network including the internet.
Cover: protocols as agreed rules (format, timing, error handling, addressing); layering (each layer serves the one
above, can be changed independently); a message's journey down and up the stack: Application (HTTP request built),
Transport (TCP splits into segments, port numbers, sequence numbers, acknowledgements and retransmission, flow
control), Internet (IP adds source/destination IP addresses, routing, packets/datagrams), Link (frames, MAC addresses,
physical transmission), reassembly at the destination; each application protocol in one exam sentence with ports only
if certain (HTTP 80, HTTPS 443, FTP 21, SMTP 25 are standard; avoid others); POP3 (download, usually delete from
server) vs IMAP (synchronise, mail stays on server); BitTorrent: tracker, swarm, seeds, peers, the file in pieces,
downloading pieces from many peers at once and uploading to others, hash checks of pieces; circuit switching
(dedicated path for the whole call: constant bandwidth, in order; wasteful, set-up time: traditional telephone
networks) vs packet switching (packets routed independently, different routes, reassembled by sequence number;
efficient, resilient; variable delay, jitter: the internet); the router's role (reads the destination IP, consults the
routing table, forwards to the next hop, decrements hop count/TTL).
- `:::def`: protocol, protocol stack, TCP/IP, each layer, HTTP, FTP, SMTP, POP3, IMAP, BitTorrent, peer, seed,
  tracker, circuit switching, packet switching, packet, router, hop.
- Pitfalls: SMTP sends, POP3/IMAP retrieve; TCP is Transport, IP is Internet; "packets all take the same route" is
  circuit-switching thinking; BitTorrent is a protocol, not a piracy tool.
- Exam-style: describe what the Transport layer does when a web page is sent (4); compare circuit and packet switching
  for a video call (4); explain how BitTorrent shares a large file (5).
- Figure: hand SVG of the four-layer stack on two hosts with a router between (Internet and Link layers only on the
  router), fig.
- Links: SME `14-communication-and-internet-technologies-/protocols/exam-questions/` and
  `…/circuit-switching-packet-switching/exam-questions/`, MDN HTTP overview, Computerphile.

## cs.hardware2 · Processors, parallel processing and virtual machines (`@time 4–6 hours`)
Outcomes (FACTS.md 15.1): RISC and CISC processors and their differences; interrupt handling on CISC and RISC;
importance and use of pipelining and registers in RISC processors; the four basic architectures SISD, SIMD, MISD,
MIMD; characteristics of massively parallel computers; the concept of a virtual machine, examples of its role, its
benefits and limitations.
Cover: RISC (few simple instructions, one clock cycle each, fixed-length format, many general-purpose registers,
load/store architecture, heavy pipelining, more work for the compiler, more RAM for programs) vs CISC (many complex
instructions, variable length and multi-cycle, fewer registers, more work in hardware/microcode, shorter programs) as
a table; pipelining in five stages (instruction fetch, instruction decode, operand fetch, instruction execute, result
write back: name them as "fetch, decode, operand fetch, execute, write back"), a timing diagram and the count of clock
cycles for n instructions with k stages (k + n − 1) vs k × n; hazards in general (a branch flushes the pipeline);
interrupts with pipelining (instructions in the pipeline must be finished or discarded; RISC uses many registers so
the state can be saved quickly; mention only what is certain); Flynn's classification with an example each (SISD:
simple single-core; SIMD: graphics/vector processors, one instruction on many data items; MISD: rare, fault-tolerant
systems such as some flight-control designs (say "rarely used"); MIMD: multicore processors, clusters); massively
parallel computers (very many processors, each with its own memory, connected by a fast network, working on parts of
one task; programs must be written for parallelism; uses: weather forecasting, simulations); virtual machines
(software emulating a computer; a host runs guest OSs via a hypervisor; process VMs such as the Java VM running
bytecode; roles: testing on other OSs, running legacy software, server consolidation, sandboxing malware; benefits
and limitations: performance overhead, hardware access).
- `:::def`: RISC, CISC, pipelining, register, SISD, SIMD, MISD, MIMD, massively parallel computer, virtual machine,
  host, guest, hypervisor.
- Pitfalls: RISC is not "slower because it has fewer instructions"; pipelining does not make one instruction faster;
  SIMD vs MIMD; a VM is slower than the real hardware.
- Exam-style: complete a pipeline diagram for 4 instructions (3); explain why RISC suits pipelining (3); give one
  benefit and one limitation of a VM for a scenario (2); identify the architecture for a description.
- Widget **cs-pipeline** in the pipelining section.
- Links: SME `15-hardware-and-virtual-machines-/processors-parallel-processing-and-virtual-machines/exam-questions/`,
  Computerphile.

## Widget spec: cs-pipeline
`<div class="widget" data-w="cs-pipeline" data-n="6" data-branch="3"></div>`
- A timing grid: rows are instructions 1..n (3–10, slider), columns are clock cycles; each cell names the stage (IF,
  ID, OF, EX, WB, with a key that spells them out). Toggle "pipelined / not pipelined" to compare total cycles
  (k + n − 1 vs k × n, shown as numbers). Optional branch at instruction b: when it executes, later instructions
  already in the pipeline are flushed (cells marked "flushed") and fetching restarts, and the cycle count updates.
- Grid as an HTML table with a caption; readable on phones (the grid scrolls inside the widget only). Test the cycle
  counts in Node.
