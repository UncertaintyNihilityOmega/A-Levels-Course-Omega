## cs.data · Number systems and binary arithmetic (`@time 6–8 hours`)
Outcomes (FACTS.md 1.1): binary magnitudes and binary vs decimal prefixes (kibi/kilo, mebi/mega, gibi/giga,
tebi/tera); binary, denary, hexadecimal, BCD, one's and two's complement; convert integers between bases and
representations; binary addition and subtraction with positive and negative integers; overflow; practical uses of
BCD and hexadecimal; character data in binary: ASCII, extended ASCII, Unicode (no codes to memorise).
Cover:
1. Why binary (two-state electronics); bit, nibble, byte; place values 128 … 1; counting in binary.
2. Prefixes: 1 KiB = 1024 bytes vs 1 kB = 1000 bytes; the table to TiB/TB; converting a size between them
   (exact, with powers of 2 and 10); why a "500 GB" drive shows about 465 GiB (compute exactly in checks).
3. Denary ↔ binary (place values and repeated division by 2), binary ↔ hex (nibbles), denary ↔ hex (via binary or
   ×16). Hex uses: memory addresses, colour codes (#RRGGBB), MAC addresses, error codes, shorter and less
   error-prone than binary.
4. BCD: each denary digit in 4 bits (packed BCD two digits per byte); uses: digital displays, clocks, calculators,
   money values where exact denary digits matter. 1001 is the largest valid nibble. Not the same as binary.
5. Negative numbers: one's complement (flip all bits; two zeros) and two's complement (flip and add 1; MSB is
   −128 in 8 bits); range of an n-bit two's complement integer −2ⁿ⁻¹ to 2ⁿ⁻¹ − 1; converting both ways.
6. Binary addition (carry rules, 1 + 1 + 1 = 11); subtraction by adding the two's complement; overflow: the result
   needs more bits than the register (unsigned carry out; signed: two positives give a negative or two negatives a
   positive). Show 8-bit examples of each.
7. Characters: character set; ASCII 7-bit (128 characters), extended ASCII 8-bit (256), Unicode (many scripts,
   emoji, more bits per character); consecutive codes for 'A'…'Z' and '0'…'9' (give the code of 'A' as 65 in a
   question, as the insert's ASC example does, never ask students to recall codes); "the code for '7' is not 7".
- `:::def`: bit, byte, nibble, denary, hexadecimal, BCD, one's complement, two's complement, overflow, character
  set, ASCII, Unicode, kibibyte.
- Python: `bin()`, `hex()`, `int("1011", 2)`, `ord()`, `chr()`, a two's complement function with masking; each
  block runs and its output is checked. Keep these as "check your answer with Python" boxes; exam answers are by
  hand.
- Pitfalls: reading hex A–F; dropping leading zeros in fixed-width answers (always write all 8 bits); confusing
  BCD with binary; forgetting the "add 1"; calling a carry out of a signed addition "overflow" when it is not.
- Exam-style: convert and show working [B1 per step]; add two 8-bit two's complement numbers and say whether
  overflow occurred; give two uses of hex/BCD; explain why Unicode is used instead of ASCII.
- Figures: place-value table as a Markdown table (no SVG needed); one hand SVG of 8-bit two's complement place
  values with −128 highlighted by a label (fig small).
- Widget **cs-binary** in the two's complement section.
- Links: SME `1-information-representation/data-representation/exam-questions/`, 101 Computing binary converter,
  Khan computers-and-internet, Unicode home.

## cs.media · Images, sound and compression (`@time 4–6 hours`)
Outcomes (FACTS.md 1.2, 1.3): bitmap encoding (pixel, file header, image resolution, screen resolution, colour
depth/bit depth); estimate bitmap file size; effect of changing resolution and colour depth on quality and size;
vector graphics (drawing object, property, drawing list); justify bitmap or vector; sound (sampling, sampling rate,
sampling resolution, analogue and digital data); effect of rate and resolution on size and accuracy; need for
compression; lossy vs lossless, justify; how text, bitmap, vector and sound files can be compressed, incl. RLE.
Cover: pixels and colour depth (2ⁿ colours); header contents (width, height, colour depth, file type, compression);
image vs screen resolution; file size = width × height × colour depth (bits) → bytes → KiB/MiB with the prefix the
question uses; vector drawing list example (circle with centre, radius, fill colour, line width) and scaling without
loss; bitmap vs vector justification table; sound: analogue wave sampled at regular intervals, sample rate (Hz),
sampling resolution (bits per sample), size = rate × resolution × seconds × channels; trade-offs; compression:
lossless (RLE, dictionary/pattern substitution for text, no data lost) vs lossy (removes data humans notice least:
reduced colour depth/resolution for images, perceptual removal of inaudible frequencies for sound); RLE worked on a
row of pixels and on text, including when RLE makes a file bigger; vector files compressed losslessly.
- `:::def`: pixel, image resolution, screen resolution, colour depth, file header, vector graphic, drawing list,
  sampling rate, sampling resolution, lossy, lossless, run-length encoding.
- Pitfalls: bits vs bytes (divide by 8); 1 KiB = 1024 bytes; colour depth is bits per pixel, not number of colours;
  RLE on data without runs; "lossy for text" is wrong (text must be lossless).
- Python: an RLE encoder and decoder (runs and output checked); a file-size function.
- Exam-style: estimate a file size with no calculator (choose numbers like 1024 × 768 × 24 bits); justify lossy for
  streamed video vs lossless for a spreadsheet; RLE an 8 × 1 pixel row.
- Figures: one hand SVG of a sampled waveform with sample points and the stepped digital version (`:::plot` can draw
  a sine; samples as `--pt`s or a hand SVG); a small pixel grid figure for RLE.
- Links: SME multimedia and compression exam questions, Khan computers-and-internet.

## Widget spec: cs-binary
`<div class="widget" data-w="cs-binary" data-bits="8" data-value="-37" data-mode="convert"></div>`
- Modes (`.w-tabs`): **Convert** (type a denary integer, or a binary/hex string; choose 4–16 bits) shows unsigned
  binary, hex, BCD (digit by digit), one's complement and two's complement with the place-value row (−2ⁿ⁻¹ for two's
  complement), and an "out of range for n bits" message instead of a wrong pattern. **Add** (two n-bit
  patterns or denary values) shows the column addition with carries, the n-bit result, the unsigned and signed
  meanings, and whether a carry out or a signed overflow occurred, in words.
- Every bit is a `<button>` that toggles (keyboard works); results in `W.readout`; no colour-only meaning
  (overflow says "Overflow").
- Validate input (bad characters, too many bits) with a `.w-err` message. Test the logic with a Node script
  against Python results for every 8-bit value.
