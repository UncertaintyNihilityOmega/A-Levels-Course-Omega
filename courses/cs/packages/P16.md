## cs.algorithms2 · Searching, sorting and Big O (`@time 6–8 hours`)
Outcomes (FACTS.md 19.1, first part): linear and binary search (write both; the conditions for binary search; how a
binary search's performance varies with the number of items); insertion sort and bubble sort (write both; performance
depends on the initial order and the number of items); comparing algorithms by criteria such as time and memory, with
Big O notation for time and space complexity.
Cover: recap of linear search (link to the gold chapter, do not repeat it); binary search on a sorted array: low,
high, mid ← (low + high) DIV 2, compare, halve; iterative pseudocode and Python; trace table with low/mid/high; the
maximum number of comparisons ⌊log₂ n⌋ + 1 (show for n = 1000: 10) and why doubling n adds one comparison; condition:
data sorted (and direct access by index); insertion sort (build a sorted part; take the next item, shift larger items
right, insert) in pseudocode and Python with a full pass-by-pass trace; bubble sort improved (flag and shrinking
boundary: link to the gold) compared with insertion sort on sorted, reversed and random data, counting comparisons and
swaps/shifts in the checks; Big O: O(1), O(log n), O(n), O(n log n) (mention as the class of faster sorts, not
examined in detail), O(n²), O(2ⁿ) with examples and a growth table for n = 10, 100, 1000 (exact values from Python);
time vs space complexity (bubble and insertion sort are in-place: O(1) extra space; recursion uses stack space: link
to cs.recursion); best/worst cases (bubble sort with a flag on sorted data is O(n); insertion sort on sorted data is
O(n); both O(n²) worst).
- `:::def`: binary search, insertion sort, time complexity, space complexity, Big O notation, best case, worst case,
  in-place algorithm.
- Pitfalls: binary search on unsorted data; mid calculation off by one and infinite loops (update low ← mid + 1, high
  ← mid − 1); Big O ignores constants; "O(log n) means log base 10".
- Exam-style (P3 and P4): write a binary search function returning the index or −1 (6); write an insertion sort
  procedure (6); state the Big O of given pseudocode with a reason (2); P4-style: "write program code for …, test it
  with the given data, show the output".
- Plot: a `:::plot` of n, n log₂ n and n² growth is fine (at most two series per plot: two plots, or n and n² only).
- Widget **cs-sort** in the sorting section and the binary search section.
- Links: SME `19-computational-thinking-and-problem-solving-/algorithms/exam-questions/`, VisuAlgo sorting, Khan

## cs.adts · Abstract data types: stacks, queues, lists, trees and graphs (`@time 7–9 hours`)
Outcomes (FACTS.md 19.1, ADT part): show understanding of and use ADTs; write algorithms to find an item in a linked
list and a binary tree; insert into a stack, queue, linked list and binary tree; delete from a stack, queue and linked
list; a graph as an ADT: key features, justify its use (no code); how ADTs can be implemented from another ADT or from
built-in types: stack, queue, linked list, dictionary, binary tree.
Cover: full pseudocode (as Cambridge writes it: global arrays, pointers, a null pointer value, a free list) and Python
(lists and classes, as Paper 4 tasks do) for: stack push/pop with overflow/underflow checks; linear and circular queue
enqueue/dequeue; linked list (array of records with Data and Pointer, StartPointer, FreeListPointer): initialise the
free list, find, insert in order, delete, output in order; binary search tree (records with LeftPointer, Data,
RightPointer, RootPointer): insert, find, in-order traversal (iterative find; recursive traversal links to
cs.recursion), and pre-order/post-order mentioned; dictionary (key–value pairs; implemented with a hash table or two
arrays; Python `dict`); graph (vertices, edges, weights, directed; adjacency list/matrix; uses in AI and networks;
justify vs a tree); implementing one ADT from another (a queue from two stacks; a stack from a linked list; a priority
queue from a list) with the reasoning; Paper 4 style OOP versions (classes Node, LinkedList, Tree) briefly, the full
OOP syntax in cs.oop.
- `:::def`: ADT, binary tree, binary search tree, root, leaf, subtree, traversal (in-order, pre-order, post-order),
  dictionary, key, graph, adjacency matrix, adjacency list, free list.
- Pitfalls: forgetting to update the free list on insert/delete; not handling the empty structure or the first node;
  `RootPointer` vs `StartPointer`; deleting from a binary tree is not required (do not teach it as examined).
- Exam-style (P3): complete the arrays of a linked list after deletions (4); write pseudocode to insert into a binary
