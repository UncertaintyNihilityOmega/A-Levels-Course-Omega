## cs.f.basics · Programming from zero: Python and pseudocode (pre)
`@level pre` · `@time 6–8 hours`. No `@paper` (pre). Long and gentle: the reader has never programmed. Every
Python example runs and shows its output (COURSE.md code rules). Pseudocode beside Python throughout.
Outcomes it prepares (FACTS.md 9.2, 11.1, 11.2 at an introductory level; the full exam depth is in
cs.algorithms and cs.programming): write input–process–output programs; sequence, selection, iteration.
Cover, in this order:
1. What a program is; source code, running, output; Python 3 (install from python.org, or the IDLE editor that
   comes with it; never name commercial products in exam answers). Why Cambridge uses pseudocode too (Paper 2 is
   on paper, any language) and Python (Paper 4).
2. `print()` and `OUTPUT`; strings and quotes; comments `#` and `//`.
3. Variables and assignment: `score = 0` and `Score ← 0`; naming rules (FACTS.md identifiers); `DECLARE`.
4. Data types at first sight: int, float, str, bool ↔ INTEGER, REAL, STRING, BOOLEAN (CHAR, DATE in cs.datatypes).
5. Arithmetic: `+ - * /`, `//` and `%` ↔ DIV and MOD (insert examples 10 DIV 3 = 3, 10 MOD 3 = 1: use your own
   numbers), precedence, `/` gives a real number in both.
6. Input: `input()` always returns a string; `int(input(…))`; `INPUT`. Show a console run (` ```text ` with the
   typed value; the checks helper supplies input).
7. Comparison and Boolean operators: `== != < > <= >=`, `and or not` ↔ `= <> < > <= >=`, `AND OR NOT`.
8. Selection: `if/elif/else` ↔ `IF … THEN … ELSE … ENDIF` (nested). Indentation matters in Python.
9. Loops: `for i in range(1, 6)` ↔ `FOR I ← 1 TO 5 … NEXT I` (range end is exclusive: the classic slip);
   `while` ↔ `WHILE … ENDWHILE`; REPEAT … UNTIL has no Python keyword: show `while True: … if …: break`.
10. Strings basics: length, joining with `+` ↔ `&`, a first look at slicing (full string functions in
    cs.programming).
11. Errors: syntax error, run-time error (division by zero, `int("abc")`), logic error; reading a Python traceback.
12. A first trace table: dry-run a 6-line loop by hand (columns for each variable and OUTPUT).
13. Putting it together: two small complete programs (a times-table printer; a guessing game without random:
    fixed secret; then with `random.randint` shown but not checked for output).
- `:::def`: program, algorithm, variable, constant, data type, assignment, selection, iteration, syntax error, logic
  error, run-time error, trace table, pseudocode.
- Pitfalls: `=` vs `==` vs `←`; `range(1, 5)` stops at 4; `input` gives text so `"3" + "4"` is `"34"`; Python is
  case sensitive (pseudocode identifiers are not, FACTS.md); forgetting the colon or the indentation; integer vs
  real division.
- Exam practice: Paper 2 style short items (output of given pseudocode, complete a trace table, write 4–6 lines of
  pseudocode from a description, identify the error type). Stretch: an FizzBuzz-style problem and a digit-sum loop.
- Figure: one hand SVG "input → process → output" with a variable box (fig small).
- Warm-up: three GCSE-level questions (arithmetic with remainders, a flowchart-free "follow these steps", a
  true/false logic statement), each naming "(GCSE)" instead of a chapter.
- Links: Python tutorial (docs.python.org), W3Schools Python, Python Tutor, Exercism Python track, CS50.
- `Next: [Number systems and binary arithmetic](#cs.data)`.
