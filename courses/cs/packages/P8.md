## cs.algorithms · Computational thinking and algorithms (`@time 5–7 hours`)
Outcomes (FACTS.md 9.1, 9.2): abstraction (need, benefits, purpose; produce an abstract model by including only
essential details); decomposition into sub-problems leading to modules (procedure/function); an algorithm is a
solution expressed as a sequence of defined steps; suitable identifier names and an identifier table; pseudocode
with input, process and output; sequence, selection and iteration; documenting an algorithm with structured English,
a flowchart or pseudocode; pseudocode from structured English or a flowchart; a flowchart from structured English or
pseudocode; stepwise refinement; logic statements to define parts of a solution.
Cover: abstraction with a map/timetable example and a "which details to keep" exercise; decomposition of a real
task (a school canteen ordering system) into a tree of sub-tasks, each becoming a module; algorithm definition;
identifier tables (identifier, data type, description) Cambridge style; structured English (numbered, imperative,
indented for selection/iteration); flowchart symbols (terminator, process, input/output parallelogram, decision
diamond with Yes/No, arrows, predefined process) drawn as hand SVGs; converting between the three forms in both
directions with two full worked examples (one with a loop, one with nested selection); stepwise refinement shown in
three levels for one problem; logic statements (conditions written as Boolean expressions, e.g. "valid if age is at
least 13 and consent is TRUE").
- `:::def`: algorithm, abstraction, decomposition, identifier, identifier table, structured English, flowchart,
  pseudocode, stepwise refinement, module.
- Pitfalls: a flowchart decision has exactly two exits labelled Yes/No; flowcharts need a single start and end
  terminator; identifier names without spaces; abstraction ≠ decomposition.
- Exam-style (Paper 2 style): complete an identifier table; write pseudocode from a given flowchart (6); draw a flowchart
  from given pseudocode; describe one benefit of abstraction for a given program; decompose a scenario.
- Figures: hand SVG flowcharts (two), each checked with coordinates, `fig` width, arrows with `#ah`.
- Widget **cs-trace** may appear here once (one program) and is used fully in cs.programming.

## cs.programming · Programming basics: variables, selection and loops (`@time 7–9 hours`)
Outcomes (FACTS.md 11.1, 11.2): implement and write pseudocode from a program flowchart or structured English;
constants (declaration and initialisation), variable declaration, assignment, arithmetic and logical expressions,
keyboard input, console output; built-in functions and library routines (string functions always given in the
insert); IF with ELSE and nested IF; CASE; count-controlled, post-condition and pre-condition loops; justify the
choice of loop.
Cover, each with pseudocode, the Python equivalent, a run with output and a trace table where it helps:
DECLARE and CONSTANT (literal values only), assignment, operators incl. DIV/MOD and `/` (REAL), precedence and
brackets, Boolean expressions with AND/OR/NOT; INPUT/OUTPUT with several values; the insert functions (LEFT, RIGHT,
MID, LENGTH, TO_UPPER, TO_LOWER, NUM_TO_STR, STR_TO_NUM, IS_NUM, ASC, CHR, INT, RAND, DAY/MONTH/YEAR/TODAY) with
Python equivalents (slicing `s[0:3]`, `s[start - 1:start - 1 + length]` for MID, `len`, `upper`, `str`, `int`/`float`,
`isdigit` with its limits, `ord`, `chr`, `int()` truncation, `random.random()*x`); IF/ELSE and nested IF; CASE with
values, ranges and OTHERWISE (Python `if/elif/else`, or `match` only as an aside); FOR with STEP (incl. negative),
REPEAT … UNTIL, WHILE … ENDWHILE; when to use each (known number of iterations; at least once, e.g. input
validation; possibly zero times, e.g. reading until a sentinel); validation loops with REPEAT; running totals,
counting, max/min of input values, sentinel-controlled input; nested loops (a times table grid); writing efficient
pseudocode (no repeated work inside loops, exit early with a condition-controlled loop).
- `:::def`: constant, variable, declaration, assignment, operator, built-in function, library routine, selection,
  CASE structure, count-controlled loop, pre-condition loop, post-condition loop, nested statement, sentinel value.
- Pitfalls: `=` in pseudocode compares (outside CONSTANT); REPEAT … UNTIL runs until the condition is TRUE (a WHILE
  runs while TRUE); MID counts from 1 in pseudocode but Python slices from 0; INT truncates (INT(−2.5) = −2: check in
  the checks file); string comparison is case sensitive (insert); FOR loop variable must not be changed inside the loop.
- Exam-style: rewrite a WHILE loop as a REPEAT loop; justify a loop choice (2); write pseudocode for a menu with CASE;
  string-processing questions with MID/LENGTH (count vowels, reverse a word, validate a code like "AB1234");
  complete a trace table for a nested loop.

## Widget spec: cs-trace
`<div class="widget" data-w="cs-trace" data-prog="total"></div>`
- Steps through a built-in pseudocode program line by line: the program is shown in a monospaced list with the current
  line marked "▶" (text, not colour only); a trace table grows below (one column per variable plus OUTPUT, a row
  added whenever a value changes, as Cambridge trace tables are drawn). Back / Next (`W.stepper`) and Reset.
- Programs (`data-prog`): `total` (WHILE with a sentinel), `grade` (nested IF), `validate` (REPEAT with inputs from a
  fixed list), `countdown` (FOR with STEP −2), `vowels` (MID/LENGTH loop). Each program's steps (line, variable
  values, output) are generated by a data/ script that runs a Python translation, and embedded as JSON in the widget
  file; the widget never interprets pseudocode itself.
- Unknown `data-prog` → `.w-err` listing the valid names.
