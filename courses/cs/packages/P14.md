## cs.translators · Compilers, BNF and Reverse Polish notation (`@time 5–7 hours`)
Outcomes (FACTS.md 16.2): how an interpreter executes a program without producing a translated version; the stages
of compilation: lexical analysis, syntax analysis, code generation and optimisation; a language's grammar as syntax
diagrams or BNF; how Reverse Polish Notation (RPN) is used to evaluate expressions.
Cover: interpreter cycle (read a statement, analyse it, execute it with its own routines, repeat; errors reported when
reached); lexical analysis (remove white space and comments, split into tokens, symbol table of identifiers with
type/address, keyword table lookup, lexical errors); syntax analysis (parse tokens against the grammar, parse tree,
syntax errors reported); code generation (object code, addresses allocated); optimisation (remove redundant code,
fewer instructions, faster/smaller program: give a before/after example); BNF: `<digit> ::= 0|1|…|9`, recursion for
repetition `<integer> ::= <digit>|<digit><integer>`, deciding whether strings are valid (show the derivation),
writing BNF for an identifier or a code format; syntax diagrams (rectangles for non-terminals, rounded boxes/circles
for terminals, loops for repetition) converted to and from BNF; RPN: infix → postfix (by bracketing and by
operator precedence; Cambridge-style questions convert both ways), evaluating RPN with a stack shown as successive
states, why compilers/interpreters use it (no brackets needed, evaluated left to right with one stack), expression
trees and post-order traversal giving RPN (link to cs.adts).
- `:::def`: lexical analysis, token, symbol table, syntax analysis, parse tree, code generation, optimisation, BNF,
  non-terminal, terminal, syntax diagram, Reverse Polish Notation.
- Pitfalls: BNF with `|` alternatives in the wrong place; forgetting operator precedence in infix → RPN; stack order
  for `−` and `÷` (second popped is the left operand).
- Exam-style: state whether strings are valid for given BNF (3); write BNF for a product code (4); convert infix to RPN
  (2) and evaluate RPN with given variable values showing the stack (4); describe lexical analysis (3).
- Python: an RPN evaluator with a list as stack and a BNF-style recursive validator for the chapter's grammar (both
  run; checks assert outputs).
- Figures: hand SVG syntax diagrams (two), checked with coordinates.
- Widget **cs-rpn** in the RPN section.
- Links: SME `16-system-software-/translation-software/exam-questions/`, 101 Computing RPN, Computerphile.

## cs.security2 · Encryption, SSL/TLS and digital certificates (`@time 4–6 hours`)
Outcomes (FACTS.md 17.1): how encryption works: public key, private key, plain text, cipher text, encryption,
symmetric and asymmetric cryptography; how keys send a private message from the public to an individual or
organisation, and a verified message to the public; how data is encrypted and decrypted with symmetric and asymmetric
cryptography; purpose, benefits and drawbacks of quantum cryptography; SSL/TLS: purpose, use in client-server
communication, situations where it is appropriate; digital certificates: how one is acquired and how it is used to
produce digital signatures.
Cover: plain text → algorithm + key → cipher text; symmetric (one shared key; fast; key distribution problem; a simple
shift or XOR cipher in Python as an illustration only, labelled "not secure") vs asymmetric (key pair; encrypt with the
recipient's public key so only their private key decrypts: confidentiality; encrypt a hash with the sender's private
key, verified with their public key: authentication/integrity); hashing and message digests; digital signatures
step by step; certificate authorities, how an organisation acquires a certificate (generate key pair, send public key
and identity to a CA, CA verifies, issues a certificate signed with the CA's private key containing the organisation's
public key, name, validity dates, serial number, CA name); how a browser checks it; SSL/TLS handshake in outline
(client hello, server sends certificate, client verifies, session key agreed using asymmetric encryption, then
symmetric encryption for the session) and where it is used (HTTPS, online banking, email, VoIP; any sensitive data);
quantum cryptography (quantum key distribution with photons; eavesdropping changes the states and is detected;
benefits: detectably secure key exchange; drawbacks: expensive, special hardware, limited distance, still developing):
keep claims general and certain.
- `:::def`: plain text, cipher text, encryption, key, symmetric encryption, asymmetric encryption, public key,
  private key, hashing, digest, digital signature, digital certificate, certificate authority, SSL/TLS, quantum
  cryptography.
- Pitfalls: a digital signature does not encrypt the message; "the public key decrypts a message encrypted with the
  public key" (wrong); TLS uses both asymmetric (handshake) and symmetric (data) encryption; a certificate does not
  contain the private key.
- Exam-style: explain how a customer sends a confidential message to a bank using asymmetric encryption (4); describe
  how a digital signature is produced and checked (5); explain how TLS secures a session (5); give one benefit and one
  drawback of quantum cryptography (2).
- Figure: hand SVG of the digital-signature process (message → hash → digest → encrypt with private key → signature;
  receiver side), fig.
- Links: SME `17-security-/encryption-encryption-protocols-and-digital-certificates/exam-questions/`, Khan cryptography,
  Computerphile.

## Widget spec: cs-rpn
`<div class="widget" data-w="cs-rpn" data-expr="(A + B) * (C - D) / E" data-vals="A=3,B=5,C=9,D=4,E=2"></div>`
- Two tabs. **Convert**: an infix expression (variables A–Z, integers, + − * / ^, brackets) → RPN with the operator
  stack shown step by step (shunting-yard; Back/Next with `W.stepper`). **Evaluate**: an RPN string with values for the
  variables → evaluation step by step, the stack drawn as a vertical list of boxes (top marked "← top"), the
  operation and result written as text each step; exact fractions for division.
- Errors (mismatched brackets, too few operands, unknown symbol) → `.w-err`. Test against the chapter's Python.
