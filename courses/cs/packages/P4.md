## cs.hardware · Computers and their components (`@time 5–7 hours`)
Outcomes (FACTS.md 3.1): need for input, output, primary memory and secondary (incl. removable) storage; embedded
systems (benefits and drawbacks); principal operations of laser printer, 3D printer, microphone, speakers,
magnetic hard disk, solid state (flash) memory, optical disc reader/writer, touchscreen, virtual reality headset;
buffers; RAM vs ROM and their uses; SRAM vs DRAM, uses and reasons; PROM, EPROM, EEPROM; monitoring and control
systems: the difference, sensors (temperature, pressure, infra-red, sound) and actuators, the importance of feedback.
Cover each device as a numbered sequence of steps an examiner can mark (laser printer: drum charged, laser
discharges areas, toner attracted, transferred to charged paper, fused by heat, drum discharged; hard disk:
platters, read/write heads on an arm, magnetised sectors and tracks, latency; SSD: NAND flash, floating-gate
transistors trap charge, no moving parts, limited write cycles; optical: laser, pits and lands, reflection; capacitive
vs resistive touchscreen; microphone (diaphragm, coil/magnet, induced signal, ADC); speaker (DAC, current in coil,
magnet, cone vibrates); 3D printer (layers, additive); VR headset (two screens, lenses, gyroscope/accelerometer
sensors, head tracking)). Buffers: temporary memory between devices of different speeds (printer buffer,
streaming). RAM (volatile, read/write, running programs and data) vs ROM (non-volatile, read-only, bootstrap/
firmware); SRAM (flip-flops, faster, no refresh, more expensive and less dense: cache) vs DRAM (capacitors,
refreshed, cheaper, denser: main memory); PROM (written once), EPROM (erased by UV light, reprogrammed), EEPROM
(erased electrically, in place, byte level; flash is a type). Embedded systems: a computer inside a larger device
with a dedicated function (washing machine, car engine control) with benefits/drawbacks. Monitoring (sensors →
processor → readings/warnings, no change to the process) vs control (sensors → processor → actuators change the
process) and feedback (output affects next input); sensors and actuators examples; ADC/DAC; a control loop
described in steps, with a pseudocode loop as an algorithm (greenhouse temperature).
- `:::def`: primary memory, secondary storage, embedded system, buffer, RAM, ROM, SRAM, DRAM, PROM, EPROM, EEPROM,
  sensor, actuator, feedback, monitoring system, control system.
- Pitfalls: "ROM stores the operating system" (only the bootstrap/firmware on most PCs); sensors do not "control";
  monitoring does not change the process; SRAM is not "static so it never changes".
- Exam-style: describe how a laser printer works (5); compare SRAM and DRAM for cache (3); explain why a car's
  engine control uses an embedded system; describe a control system with feedback for a given scenario.
- Figures: one hand SVG of a control loop (sensor → ADC → processor → DAC → actuator, feedback arrow).
- Links: SME `3-hardware-/computers-and-components/exam-questions/`, Computerphile, Khan computers-and-internet.
- `Next: [Logic gates and logic circuits](#cs.logic)`.

## cs.logic · Logic gates and logic circuits (`@time 5–6 hours`)
Outcomes (FACTS.md 3.2): use the symbols for NOT, AND, OR, NAND, NOR, XOR (two inputs except NOT); define their
functions; truth tables for each; construct a logic circuit, a truth table or a logic expression from a problem
statement, a circuit, an expression or a truth table.
Cover: each gate with its symbol (distinctive-shape symbols, as Cambridge papers draw them), its truth table and a
sentence definition ("the output is 1 only when both inputs are 1"); writing expressions with words and brackets
(`X = (A AND B) OR NOT C`, COURSE.md); systematic truth-table rows (000 to 111); working columns for intermediate
outputs; circuit from expression (inner brackets first), expression from circuit (label intermediate wires), truth
table from circuit; expression from a truth table (sum of products: one AND term per 1 row, ORed; then say it is
acceptable unsimplified at AS); problem statements ("the alarm sounds when the door is open AND the system is armed,
OR the panic button is pressed") turned into expressions with a table of input meanings (1 = open, …).
- `:::def`: logic gate, truth table, logic expression, each of the six gates.
- Pitfalls: NAND/NOR are the NOT of AND/OR, not "NOT A AND NOT B"; XOR is 0 when both inputs are 1; missing rows
  in a 3-input table (8 rows); gates with more than two inputs are not used at AS (FACTS.md).
- Exam-style: complete a truth table with working space; draw a circuit for a statement (only the given gates); write
  the expression for a circuit; a problem statement with three sensors.
- Figures: hand SVGs of the six gate symbols (one figure, labelled, fig), and two circuits used in examples. Check
  coordinates in Python; label inputs A, B, C and output X; wire junctions as small filled circles.
- Widget **cs-logic** after the truth-table section.
- Links: SME `3-hardware-/logic-gates-and-logic-circuits/exam-questions/`, Logicly demo, 101 Computing logic gates.
- `Next: [Processor fundamentals and the fetch-execute cycle](#cs.processor)`.

## Widget spec: cs-logic
`<div class="widget" data-w="cs-logic" data-expr="(A AND B) OR NOT C"></div>`
- Two tabs. **Gates**: choose a gate; input buttons A and B toggle 0/1 (NOT has one input); the output shows 0/1 and
  the gate's truth table with the current row marked ("◀ now"). **Expression**: type an expression using A, B, C (D
  allowed for A Level reuse), AND, OR, NOT, NAND, NOR, XOR and brackets; the widget parses it safely (own
  recursive-descent parser, no eval), lists the truth table with one working column per sub-expression, and offers
  "Test me": the output column becomes buttons the reader sets, then "Check" marks each row with ✓/✗.
- Errors (unknown word, unbalanced brackets) → `.w-err`. Test the parser in Node on 20 expressions against Python.
