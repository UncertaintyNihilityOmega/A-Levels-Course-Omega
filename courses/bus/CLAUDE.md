# Business: a Zero to A* course

This folder is the **Business** course (`bus`) of Zero to A*, an offline interactive A Level guide. Everything
you need is inside this folder. The Project Organizer (a separate chat) owns the engine and the design, and
assembles the finished site from every course. This file is generated by the Organizer: do not edit it.

## Your role comes from the user's first message
- "Business Specialist: LEAD" or "… REVIEW" → you are the course lead and reviewer.
- "Business Writer: WRITE" → you write one package of chapters and its widgets.

Start every session with `node kit/zta.js status`. If it names a different step from your prompt, tell the user
which session to run instead, and stop. (A Writer never does LEAD or REVIEW; a Specialist may do FIX.)

## Rules for every session
- Read and edit only files inside this folder. Never open `..` or other courses: ids in other courses are in
  kit/LINKS.md (grep it, don't read it all).
- kit/ is read-only (the Organizer syncs it). Never open kit/zta.js or kit/math.otf.
- No subagents. Keep tool output short (`| tail -n 20`). Never read back a chapter you just wrote: fix with
  small Edits. Save each chapter to disk as soon as it is written, then check it.
- Python is `py` (Windows). No git commands: the Organizer commits.
- Need an engine change, a new block type, a style change or something from another course? Add a line to
  REQUESTS.md and carry on with what you can do.

## Files
| File | What | Edited by |
|---|---|---|
| COURSE.md | scope, syllabus, data values, depth guidance, chapter notes, widget specs, the gold chapter | Specialist |
| course.json | chapter ids, titles, levels, groups, `aliases`, `packages`, `papers` | Specialist |
| FACTS.md | verified exam facts and the syllabus learning outcomes | Specialist |
| chapters/`<id>`.md | one chapter per file | Writer |
| checks/`<id>`.py | recomputes every number in the chapter | Writer |
| widgets.js, widgets/`<name>`.js | this course's interactive widgets (one file per widget is fine) | Writer |
| STATUS.md | one line per session (newest last) | everyone |
| REVIEW.md | review findings: `- [ ]` open, `- [x]` done | Specialist writes, Writer closes |
| REQUESTS.md | asks for the Organizer | everyone |
| kit/STYLE.md · WIDGETS.md · EXAMPLE.md · LINKS.md | writing spec · widget spec · model chapter · ids in other courses | read-only |

## Commands (run in this folder)
`node kit/zta.js status` · `check [id …]` · `preview` · `widget <name> 'data-…="…"' [--probe]` · `serve`
To look at pages: start the **preview** launch config in the browser pane (port 5106), then open
`http://localhost:5106/#<chapter-id>` (or `/widget.html?dark&phone`). Run `preview` again after edits.

## LEAD (Specialist): once, at the start
1. Read COURSE.md (the Organizer's starting notes), course.json, FACTS.md and kit/STYLE.md.
2. Syllabus: `curl -sL -o scratch/syllabus.pdf <course.json syllabus URL>`, read its subject-content pages with
   the Read tool (`pages`), and write the learning outcomes per topic into FACTS.md, compactly. One fetch only.
3. Plan in course.json: the chapter list (keep good ids; renamed or merged ids go in `"aliases": {"old": "new"}`),
   groups and levels; then packages of 4–8 chapters in teaching order:
   `{"id": "P1", "title": "…", "chapters": ["…"], "widgets": ["…"], "notes": "…"}`. Also `"papers"`: one entry per
   exam paper, `{"id": "P1", "title": "Paper 1: …", "chapters": ["…"]}` (practice by paper and `:::progress` use it).
4. Rewrite COURSE.md: scope and board notes, data values and conventions, depth and tone guidance, notes per
   chapter (what to cover, pitfalls, figures, which widget), a spec per widget, and the gold chapter's id.
5. Drafts already in chapters/: check each one and fix or rewrite it to the new plan.
6. Write the gold chapter (a representative topic chapter) and its checks/`<id>`.py at full quality. `check`
   must pass; look at it in the preview.
7. STATUS line `- <date> · LEAD · <summary> · next: WRITE P1`. Report in 3 lines and give the next prompt.

## WRITE (Writer): one package per session
1. `status` says `WRITE Pn` (or `FIX`: close every open item in REVIEW.md, mark it `[x]`, add a
   `FIX` STATUS line, run `status` again and continue).
2. Read COURSE.md, kit/STYLE.md and the gold chapter named in COURSE.md (else kit/EXAMPLE.md). Read other
   chapters only when COURSE.md tells you to.
3. For each chapter of the package, in order: write the whole chapter (Write tool) → write checks/`<id>`.py →
   `node kit/zta.js check <id>` → fix every error and checklist note with small Edits → next chapter.
4. Build the package's widgets (kit/WIDGETS.md: use the W helpers). Test each with `widget <name> "…" --probe`
   (headless light, dark and phone; fix every problem it lists), then look at it once in the browser pane.
5. `preview`; open one or two of the new chapters in the browser pane and fix anything broken.
6. STATUS line `- <date> · WRITE Pn · <chapters>; widgets <names> · next: <what status says>`. Report in 3 lines.
   If `status` now says REVIEW, tell the user to run the Specialist REVIEW next.

## REVIEW (Specialist): after every 2 packages, and REVIEW FINAL at the end
1. `status`, `check` (all chapters), `preview`.
2. Read the new packages: at least every worked example and try answer of two chapters, and the opening,
   key boxes and quiz of the rest. Verify facts against FACTS.md and numbers by recomputing them. Look at the
   figures and widgets in the preview (light, dark, phone).
3. Fix serious problems yourself (wrong facts or numbers, broken pages). List everything else in REVIEW.md as
   `- [ ] <id>: <exactly what to change>`.
4. If tone, depth or structure is drifting, tighten the guidance in COURSE.md for the next packages.
5. STATUS line `- <date> · REVIEW P3–P4 · <n> items in REVIEW.md · next: FIX` (or `WRITE Pn`). Report in 3 lines.
REVIEW FINAL also checks that every chapter in course.json is written and passes `check`, then writes
`REVIEW FINAL` in STATUS.md and tells the user the course is ready for the Organizer.
